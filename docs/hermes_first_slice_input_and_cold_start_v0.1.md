# 1. 敏捷收敛背景：从“多源感知”到“单工具深度聚焦”

在前期设计中，系统规划了对 Hermes、ChatGPT 网页版、Codex、Pi 等多工具的跨端感知。然而从敏捷开发与落地角度看，多工具同时接入面临极高的工程摩擦：

- 浏览器插件抓取网页版存在防爬、鉴权及界面更新失效风险；
- 多源异构数据混合大幅增加底层归因与清洗复杂度；
- 容易分散注意力，导致核心成长逻辑迟迟无法跑通。

因此，第一阶段确立核心收敛原则：

# Focus on Hermes, Feed by Hand.

中文：

> **自动化只抓 Hermes，跨场景全靠随手投喂。**

这样既能以极低成本直接获得最高质量的 Agent 决策节点，又保留了用户将外部生活与灵感切片注入系统的通道。

# 2. 随手投喂切片（Slice Feeding）机制设计

## 2.1 核心定位与原则

随手投喂切片是整个系统的**低摩擦主观输入通道**。

它坚决不是：
- 日记软件（无需排版、标题、日期）；
- 任务复盘总结（绝不强迫用户写“我学到了什么”）；
- 问卷系统或打卡任务。

它的本质是：
> **用户在桌面上随时可以把一段文本“扔”给桌宠，让它默默吞下并沉淀到记忆库。**

用户可以扔的内容包括：
- 在 ChatGPT / Pi / 网页中看到的精彩论述与推演；
- 调试代码或做架构权衡时的即时灵感；
- 读到《悉达多》《鱼不存在》等文字时的随感；
- 甚至是一两句纯粹的吐槽与情绪宣泄。

---

## 2.2 极简呼出与输入人机工学（Ergonomics）

为了做到“极低摩擦、不打断工作流”，输入体验必须做到极致轻量：

1. **触发方式**：
   - 全局快捷键（例如快速双击 `Alt` 或快捷键 `Win + Shift + P`）；
   - 或鼠标直接点击桌面宠物身躯。
2. **UI 形态**：
   - 在桌宠旁边呼出一个无边框、半透明、巴掌大的极简文本框；
   - 支持文字粘贴（`Ctrl + V`）与直接拖拽选中文本释放；
   - 敲击 `Enter`（或 `Ctrl + Enter`）即时发送并自动收起，`Esc` 随时取消。
3. **前台即时反馈规范（Hard Rule）**：
   - **严禁即时大段心理分析**：绝不能像聊天机器人一样立即回复 500 字说教；
   - **严禁追问**：不主动问“你为什么这么想？”；
   - **以动作与质朴短语为主**：
     - 桌宠做一个收进背包、放上书架或轻轻点头的动画；
     - 附带 5~10 字以内的平实回应（例如：“记下了”、“存进抽屉了”、“收到了”）。

---

## 2.3 切片数据的归宿与生命周期

随手投喂的内容在后台被打上 `actor: user` 和 `type: raw_slice` 标签：

```text
用户随手投喂一段文本
        ↓
本地即时归档 (Raw Slice Store)
        ↓
前台给予极简确认动作 (不打扰)
        ↓
等待系统进入周期性反思 (Weekly/Monthly Reflector)
        ↓
作为 Self-report 与价值观分析的高权重证据
```

# 3. 冷启动破冰设计：前 14 天的陪伴感与灵魂建立

## 3.1 为什么必须设计专门的冷启动？

此前确立的原则是：
- `Observe by default`（默认观察，90% 信号吞掉）；
- 深层心智模式需要跨月、跨情境的长期数据支撑。

但如果前 14 天完全贯彻这些原则，系统在前两周会表现得像一个**没有任何交互、没有任何灵性的死物贴图**，用户会迅速失去耐心并关闭软件。

冷启动的核心目标是：
> **在前两周数据量不足以做深层心理推断的前提下，如何既不“自作聪明胡乱算命”，又能让用户强烈感受到“它真实在场，并且在看着我”？**

建议将前两周分为三个渐进微阶段。

---

## 3.2 阶段一：初见与调频（Day 1 ~ Day 3）

### 核心定位
**“物理在场，安静调频”**。建立宠物与 Hermes 的联动，100% 动作在场，0% 心理推断。

### 行为表现
1. **首次启动台词**：
   极为低调平实，绝无谄媚与说教：
   > *“刚到你的桌面。你忙你的，我先熟悉一下你的工作节奏。”*
2. **Hermes 状态机动作映射**：
   - Hermes 开始推理/思考 → 宠物戴上眼镜托腮；
   - Hermes 调用工具/搜索 → 宠物翻开书本或拿出工具；
   - Hermes 遇到报错重试 → 宠物抓抓耳朵或整理桌面；
   - 任务成功完成 → 宠物轻轻举手示意。
3. **言语互动**：
   - 每日主动发声上限：**0 ~ 1 次**；
   - 仅限最基础的开机问候或下线道别。

---

## 3.3 阶段二：事实镜子（Day 4 ~ Day 7）

### 核心定位
**“状态关怀与投喂回响”**。开始反映客观使用节律，让用户确认“自己的输入被真实消化了”。

### 行为表现
1. **即时状态关怀（State-level Care）**：
   - 如果用户连续高负荷运行 Hermes 超过 3 小时，或深夜 2 点仍在线：
     > *“今天这个任务折腾挺久了，先歇口气？”*
   - 若用户表示还要继续，宠物进入 Cooldown 保持安静陪伴，不再重复催促。
2. **投喂切片的回响（Echo of Slices）**：
   - 如果用户在前几天投喂了 2~3 段文字，在某次空闲或任务间歇，宠物以极简方式体现记忆：
     > *“前两天你随手记的那条关于确定性的想法，我理好了。等你想看的时候随时翻。”*
   - 此时不展开宏大叙事，仅仅证明“它真的记住了”。

---

## 3.4 阶段三：首度校准试水（Day 8 ~ Day 14）

### 核心定位
**“抛出第一面镜子”**。尝试建立第一次双向认知对齐（Calibration）。

### 触发时机
选在周末、周五晚间或一次长任务顺利闭环后的平稳时刻。

### 交互标准话术
基于过去一周 Hermes 的客观事实，提出一个**非评价性的习惯询问**：
> *“看你跑了一周 Hermes，有个小习惯挺有意思：每次遇到报错，你通常习惯连续硬调好几次才停，哪怕 Agent 建议重置方案。这是你在攻坚时的常规节奏吗？”*

### 用户的三种可能反馈与系统处理：
1. **用户确认**（*“对，我习惯先把一条路走透”*）：
   - 系统将该模式置信度提升，记录为经过验证的初始偏好；
   - 宠物平实回应：*“明白了，那我以后知道你在调什么了。”*
2. **用户否认/补充**（*“没有，只是这周这个项目结构太特殊”*）：
   - 系统立即纠偏，将该模式标记为特殊情境，不泛化为人格特征；
   - 宠物回应：*“原来是这样，那我再多看看。”*
3. **用户忽略/未理会**：
   - 系统自动静默收回该话题，不反复追问。

# 4. 首次校准（First Calibration）的设计规范

首次校准是宠物生命周期中的**里程碑事件**，必须严格遵循以下规范：

| 维度 | 正确做法 (Do) | 错误做法 (Don't) |
| :--- | :--- | :--- |
| **观察依据** | 具体的 Hermes 交互事实（如报错后的连续选择、深夜频率） | 抽象心理词汇（“你很焦虑”、“你追求完美”） |
| **表达口吻** | 平实、好奇、同行者交流（“有个小习惯挺有意思……”） | 判官定论、老师评卷（“根据系统分析，你属于……”） |
| **后续动作** | 用户回应后简短归档，恢复安静 | 顺杆爬、借题发挥展开长篇心理辅导 |

# 5. 本模块系统硬约束（System Invariants）

### Invariant 1: Slice Input Acknowledged Without Preaching
用户随手投喂切片必须得到即时确认（动作或简短短语），但**严禁立即进行未经请求的深层心理解析与说教**。

---

### Invariant 2: Ambient Presence Over Premature Inference
冷启动阶段优先通过桌宠动作机与任务状态保持“在场感”，**严禁在数据积累不足时提前下人格结论**。

---

### Invariant 3: Calibration As A Factual Habit Query
首次认知校准必须包装为对客观工作习惯的试探性询问，**绝不能表达成人格诊断书**。

---

### Invariant 4: Strategic Single-Tool Boundary
第一阶段感知边界严格锁定在 **Hermes 事件流 + 本地输入框**，在核心成长闭环验证通过前，绝不盲目扩张其他工具的自动化采集。

---

# 6. 第一阶段（Sprint 1）交付物检查清单

依据敏捷原则，本模块在 Sprint 1 的落地验收标准包括：

- [ ] **Windows 桌面挂件底座**：可正常渲染透明通道小动物，具备基础动作状态机（Idle / Thinking / Coding / Celebrate / Rest）；
- [ ] **全局极简输入框**：快捷键呼出，输入文本后自动存入本地切片数据库并给予动作反馈；
- [ ] **Hermes 事件桥接**：能读取 Hermes 的核心起止与执行状态，并驱动挂件动作切换；
- [ ] **冷启动状态机**：前 14 天严格按 Day 1~3、Day 4~7、Day 8~14 规则限制发言频次与内容深度。
