# 1. 战略转折：主从关系与宿主归属的彻底反转

在前期调研中，曾因发现 Hermes 内部具备成熟的 Petdex 机制，一度考虑将桌宠作为 Hermes 的内置插件。然而经过深入讨论，明确了决定产品生死的最高原则：

# Host Inversion: The Companion Is The Host, Not A Guest.

中文：
> **主从反转：桌宠是独立常驻的桌面宿主，AI Agents 只是它的感官天线。**

### 两种拓扑的本质区别：

```text
【错误模式：寄生型 (Parasitic)】
Hermes Agent ────(内置)────► Pet Overlay
* 致命缺陷：关掉 Hermes 宠物消失；用 ChatGPT/Codex 时桌宠不在；只是单个工具的吉祥物。

【正确模式：独立共生型 (Independent Symbiosis)】
Hermes ───┐
Pi ───────┼───► [Agent Bridges] ──┐
Codex ────┤                       │ (推流状态)
ChatGPT ──┘ (快捷键投喂)           ▼
┌─────────────────────────────────────────────────────────────┐
│             独立常驻 Companion Runtime (宿主本体)            │
│  - 独立进程，全天常驻桌角，不依赖任何特定 AI 运行             │
│  - 桌面实体表现 (透明置顶、眼球追踪、呼吸、闲置打盹)          │
│  - 随手投喂切片通道 (随时吸收跨工具灵感与生活感悟)           │
│  - 独立 Growth Core & 长期记忆 (用户心智、避风港、人生章节)   │
└─────────────────────────────────────────────────────────────┘
```

**系统底线标准（Invariants）：**
- 关掉 Hermes，宠物还在；
- 关掉 Pi，宠物还在；
- 今天不写代码、不开任何 Agent，只在浏览网页或休息，它依然在桌角安静陪伴。

# 3. 首选底座 `Clawd on Desk` 的八维深度技术穿透剖析

针对第一顺位项目 `rullerzhou-afk/clawd-on-desk`（6.4k+ Stars），结合其源码结构展开 8 维工程评估：

### 维度 1：进程独立性与全天常驻（无 Agent 时的原生生命感）
- **实现机制**：基于 Electron 的独立桌面应用程序，拥有原生单实例锁与系统托盘管理。
- **无 Agent 场景表现**：
  - 常驻桌面，不抢焦点，透明区域点击自然穿透至下方窗口；
  - 待机时具备**光标眼球追踪（Eye-tracking）**、身体微倾与阴影拉伸；
  - 闲置 60 秒后自动触发三段式**睡眠序列**（打哈欠 → 打瞌睡 → 倒下睡眠），鼠标滑动触发惊醒动画；
  - 支持**极简模式（Mini Mode）**：拖拽至屏幕右边缘自动吸附隐藏，仅露半身，悬停时探头招手。
- **结论**：**100% 具备独立生命体质感，完全脱离 Agent 生存。**

### 维度 2：多 Agent 并发与状态优先级仲裁
- **实现机制**：内部实现 `Multi-Session Priority State Machine`，接入的所有 Agent 携带独立 `session_id`。
- **仲裁规则**：
  $$\text{Failed / Error} > \text{Subagents Juggling} > \text{Working / Tool Run} > \text{Thinking} > \text{Done} > \text{Idle}$$
  并设有 `minDisplay` 最小保留时间，防止多工具并发时宠物动画高频抽搐。
- **结论**：**原生支持 Hermes + Codex + Pi 同时运行，状态清晰不混乱。**

### 维度 3：Hermes、Pi、Codex 的真实解耦机制
- **实现机制**：
  - **Hermes**：通过 `~/.hermes/plugins/` 安装轻量伴生插件，监听声明周期向本地端口推流；
  - **Pi**：安装至 `~/.pi/agent/extensions/clawd-on-desk` 全局扩展；
  - **Codex**：通过 Codex CLI 的 Session 日志与标准 Hooks 捕获。
- **解耦度**：各个 Agent 与桌宠仅通过本地回环地址（`http://127.0.0.1:23334`）单向通信。Agent 闪退或关闭，桌宠毫无影响，自动平滑切回待机发呆。
- **结论**：**桥接极其干净，属于纯粹的外部事件观察者。**

### 维度 4：外部 Growth Core 的驱动能力
- **实现机制**：Clawd 原生暴露 `Custom HTTP Agent` 开放接口：
  ```http
  POST http://127.0.0.1:23334/state
  Content-Type: application/json

  {
    "state": "thinking",
    "session_id": "growth_core",
    "message": "窗外的风挺舒服的。那个 bug 我们明天再看。"
  }
  ```
- **结论**：**我们的 Python Growth Core 无需碰 Clawd 的一行源码，直接像发 Webhook 一样即可精准调度桌宠动作与头顶气泡。**

### 维度 5：随手投喂切片（Slice Feeding）的扩展路径
- **落地路径**：
  - **方案 A（外置极简弹窗，最推荐）**：在 Python Growth Core 中监听全局热键（如双击 `Alt` 或 `Win+Shift+P`），弹出一个无边框半透明文本框，回车存入本地 Markdown/SQLite，并驱动桌宠轻微点头确认。
  - **方案 B（利用现有气泡窗口）**：Clawd 原本已有用于权限审核的 `speech.html` 独立窗口，稍作定制即可支持反向文本输入。
- **结论**：**完全不构成技术瓶颈，Sprint 1 即可轻松跑通。**

### 维度 6：Agent 状态与用户心智状态的物理隔离
- **架构保障**：
  - **Agent State**：Hermes/Pi 调工具、报错等客观操作，由 Clawd 的 Hook 接收并仅映射为“打字、思考、报错”等肢体动效；
  - **User Mind State**：连续工作负荷、用户随手投喂的感悟、避风港熔断、心理灵活性透镜推断，全部保留在 **Python Growth Core** 内部；
  - 桌宠绝不会因为 Hermes 重试 10 次就擅自弹气泡骂用户焦虑。
- **结论**：**在物理架构上杜绝了“把 Agent 行为误判为人格”的风险。**

### 维度 7：许可证合规与美术资产自由替换
- **代码许可**：AGPL-3.0，本地单机运行或自用修改完全无合规风险。
- **美术解耦**：
  - 角色本体支持 SVG、GIF、APNG、WebP；
  - **原生支持导入 Codex Pet / Petdex 8×9 精灵图包（`spritesheet.webp`）**；
  - 可以随时将形象无缝替换为三花猫、小柴犬、招财猫等任何开源像素形象，摆脱特定角色设定绑定。

### 维度 8：移动端就绪与未来 AIRI 迁移平滑度
- **移动端现成红利**：Clawd 官方已开发了局域网 **Mobile PWA 镜像**，手机扫码即可实时查看桌宠状态与活跃会话。
- **终局解耦保障**：因为心智逻辑完全封存在 Python Growth Core 中，未来若升级至 3D 虚拟人 Project AIRI，只需将通信目标地址更改为 AIRI 的 Plugin 端点，**全部成长章节、记忆沉淀与关系资产 100% 无损迁移**。

# 5. 阶段交付物与里程碑目标

完成上述第一阶段（Sprint 1）后，系统将达成以下核心里程碑：

1. **桌面上拥有一个真实存在、不需要任何 AI 也能常驻的独立萌宠**；
2. **当你使用 Hermes、Pi、Codex 时，它能看懂你在忙什么，并做出同步动作**；
3. **当你在任何地方（包括 ChatGPT 网页版）看到好的内容或产生灵感，随时按快捷键喂给它，它能稳妥存盘**；
4. **系统严格执行“默认沉默与避风港模式”，绝不打扰，绝不说教**。

在这个最小骨架稳定运行之后，我们再从容切入第二阶段：引入 `O-Mem` 的分层架构和 `Hindsight` 的高阶反思，让它周期性地为你生成属于你们的 **人生章节（Growth Chapters）**。
